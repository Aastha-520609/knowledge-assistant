# AI Engineering Documentation Assistant

A production-style RAG (Retrieval-Augmented Generation) system that answers questions over pre-indexed AI engineering documentation — LangGraph, LangChain, FastAPI, and Qdrant.

---

## Architecture (Current — Phase 7, Complete)

```
User Query
    │
    ▼
[Streamlit UI]  ──  source filter (optional)
    │
    ▼
[QueryRewriter]  ──  rewrites question into retrieval-optimized query (preserves 'what is/are' form)
    │
    ▼
[MultiQueryGenerator]  ──  generates 3 variations → 4 total queries
    │
    ▼
[Retriever]  ──  hits ChromaDB once per query, deduplicates, returns up to ~32 unique chunks
    │
    ▼
[RelevanceFilter]  ──  procedural queries: top-12 by score, no threshold
                    ──  concept queries: cosine similarity ≥ 0.25, capped at top-12
    │
    ▼
[Reranker]  ──  embedding reranker — declarative anchor sentence, cosine similarity, keeps top-6
    │
    ▼
[ContextBuilder]  ──  groups chunks by source, assembles structured context string
    │
    ▼
[AnswerGenerator]  ──  question-type-aware prompt + conversation history
    │
    ▼
[CitationFormatter]  ──  URL keyword match — only cites pages whose URL contains the concept keyword
    │
    ▼
[Answer + Citations]  ──  returned to UI, citations shown in expander
```

## Phases Completed

### Phase 1 — Basic RAG MVP
- Single source ingestion via LangChain SitemapLoader
- HTML cleaning with BeautifulSoup (removes nav, footer, scripts)
- Chunking: 1000 chars, 150 overlap via RecursiveCharacterTextSplitter
- Embeddings: `all-MiniLM-L6-v2` runs locally, no API key needed
- Vector store: ChromaDB persisted to `data/chroma/`
- Retrieval: top-6 chunks by cosine similarity
- Answer generation via Groq LLM
- Streamlit chat UI with message history and citations expander

### Phase 2 — Multi-Source Knowledge Base
- 4 documentation sources added: LangGraph, LangChain, FastAPI, Qdrant (defined in `sources.py`)
- Each chunk tagged with `source_type` and `source_display` metadata at ingest time
- Metadata filtering at retrieval — query one source or all sources
- Dynamic source dropdown in UI — adding a new source to `sources.py` auto-adds it to the dropdown
- Citation format: `SourceName — URL`
- All sources stored in one ChromaDB collection, separated by metadata tags

### Phase 3 — LangGraph Workflow Orchestration
- Replaced single LCEL chain with a LangGraph `StateGraph` (`graph.py`)
- Pipeline: `query_rewriter` → `retriever` → `relevance_filter` → `context_builder` → `answer_generator` → `citation_formatter`
- `query_rewriter`: rewrites user question into retrieval-optimized query — preserves exact terms, adds tool name
- `relevance_filter`: LLM judges each chunk yes/no — keeps only chunks that define or explain the concept asked
- `context_builder`: groups chunks by source, assembles structured context string with labeled sections
- `answer_generator`: question-type-aware prompt — answer shape adapts to what/how/why/comparison questions
- `citation_formatter`: only cites sources whose keywords appear in the generated answer

### Phase 4 — Retrieval Improvements
- `multi_query_generator` node added: generates 3 query variations → 4 total queries hit ChromaDB per question
- Deduplication across all query results by `page_content` — no duplicate chunks passed downstream
- `reranker` node added: scores each chunk 1-10 on direct relevance, keeps top-6 before context is built
- k increased from 15→20 in `retriever.py` to cast a wider net and surface lower-ranked pages
- `ingest.py` nav-strip fix: `extract_text` detects BeautifulSoup object via `hasattr(content, 'find')`, uses `soup.find("article")` as container — removes sidebar nav pollution that was filling chunks with menu links
- Re-ingested all 4 sources after fix: total chunks dropped from 10047→8157 (Qdrant: 4599→3460), confirming nav content removed
- Prompt fixes on `query_rewriter` and `multi_query_generator` to prevent synonym drift (e.g. "relationships/entities/vertices" replacing "connections/edges")
- Key discovery: LangChain `SitemapLoader` passes a pre-parsed `BeautifulSoup` object to `parsing_function`, not raw HTML — must use `hasattr(content, 'find')` to detect and use it directly

### Phase 5 — Embedding Filter + Conversation Memory
- LLM-based `relevance_filter` replaced with embedding cosine similarity scoring
- `SentenceTransformer("all-MiniLM-L6-v2")` loaded once at module level — same model already in project
- Question encoded once, each chunk scored against it, chunks with similarity ≥ 0.25 kept
- Zero LLM calls in filter — no more 429 rate limit crashes, fully deterministic
- `chat_history` added to `GraphState` — last 6 messages (3 turns) passed from UI on every query
- `answer_generator` prepends conversation history to prompt — LLM can now resolve follow-up questions like "how do I create one?"
- `query_rewriter` also receives `chat_history` — resolves pronouns like "one", "it", "this" before retrieval
- Changes: `graph.py` (filter + state + answer prompt + rewriter history), `chain.py` (history param), `ui.py` (history extraction)

### Phase 6 — Embedding Reranker + Retrieval Robustness
- LLM reranker replaced with deterministic embedding reranker — zero LLM calls, no drift
- Reranker converts rewritten query into a declarative anchor sentence before scoring:
  - `"what is a Qdrant collection"` → `"Qdrant collection is. A Qdrant collection defines"`
  - `"how to create a Qdrant collection"` → `"Create a Qdrant collection. Create a Qdrant collection API parameters"`
- Anchor sentence matches reference-doc vocabulary better than question-shaped sentences
- `relevance_filter`: procedural queries (`how to`, `how do`, `steps to`, `how can`) skip threshold entirely — pass top-12 by embedding score to reranker
- `relevance_filter`: concept queries capped at top-12 before reranker — prevents scoring drift over 30 chunks
- `query_rewriter`: explicit rule added to preserve `what is / what are` question form unchanged
- `query_rewriter`: `what are` example added to few-shot prompt
- Changes: `graph.py` (reranker fully replaced, relevance_filter procedural bypass + cap, rewriter prompt)

### Phase 7 — URL Keyword Boost + Citation Precision
- URL-based score boost added to reranker: chunks whose URL contains the concept keyword extracted from the rewritten query receive +0.15 score bonus
- Keyword extracted from rewritten query — last meaningful word (len > 3), excluding stop words and tool names
- e.g. keyword `"collection"` boosts `manage-data/collections/` over `voltagent/`, `administration/` which score similarly on embedding alone
- `citation_formatter` updated to use same keyword logic — only cites URLs containing the concept keyword
- Fallback in both reranker and citation_formatter: if no URL matches the keyword, all docs used (avoids empty results)
- Verified: `collections/` now ranks #1 and #2 for both definition and procedural collection queries
- Citation output is clean — only the canonical page cited, no ops/integration pages
- Changes: `graph.py` (reranker URL boost, citation_formatter keyword URL match)

## Setup

### 1. Install dependencies
```bash
pip install -r requirements.txt
```

### 2. Set environment variables
Create a `.env` file:
```
GROQ_API_KEY=<your_groq_api_key>
USER_AGENT=rag-assistant/1.0
```

### 3. Ingest documentation
```bash
python -m app.ingest
```
Crawls all 4 documentation sources, strips HTML noise (article container only), chunks, embeds, and saves to `data/chroma/`. Run once — vectors persist on disk.

### 4. Run the app
```bash
streamlit run app/ui.py
```

## How It Works

**Ingestion (offline, run once):**
1. `sources.py` defines each documentation source with its sitemap URL and filter prefix
2. `ingest.py` crawls each sitemap, uses `soup.find("article")` to extract only page body content (no sidebar nav)
3. Each chunk is tagged with `source_type` (e.g. `"qdrant"`) and `source_display` (e.g. `"Qdrant"`)
4. All chunks are embedded with `all-MiniLM-L6-v2` and stored in ChromaDB

**Query (runtime, every question):**
1. User types a question and optionally selects a source filter in the UI
2. `query_rewriter` rewrites the question into a precise retrieval query — preserves exact terms
3. `multi_query_generator` produces 3 variations → 4 total queries hit ChromaDB
4. `retriever` deduplicates results across all queries — up to ~32 unique chunks
5. `relevance_filter` drops chunks not directly about the concept asked
6. `reranker` converts rewritten query to declarative anchor, scores chunks by cosine similarity, keeps top-6
7. `context_builder` assembles chunks into a structured context string grouped by source
8. `answer_generator` generates a grounded answer using the context
9. `citation_formatter` extracts concept keyword from rewritten query, cites only URLs containing that keyword
10. Answer and citations returned to the UI
